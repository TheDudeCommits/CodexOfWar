# Codex of War progress ledger

This Vinext site presents the checked-in Three.js production ledger, latest
public browser evidence, canonical review contract, acceptance gate, and
preserved legacy Unity plus active browser builder-critic round history for
Codex of War.

## Local development

```bash
npm ci
npm run dev
```

The development server uses [http://localhost:3000](http://localhost:3000).

## Validation

```bash
npm run lint
npm run build
npm test
```

`npm test` server-renders the page, verifies the preserved P00–P25 ledger and
the P30/P31 browser lane, checks historical filed artifacts through P30
Round008, and enforces the public-safety contract for rejected evidence,
selected critic-review candidates, and pending verdicts.

## Data ownership

- `public/data/codex-of-war.json` is the production ledger.
- `public/data/P00-round-001-manifest.json` is the round-scoped manifest. An
  intentional recapture refreshes it; committed history preserves filed
  revisions.
- `public/data/P30-round-001.json` is the sanitized, aggregate-only public
  record for the rejected browser-foundation critic round.
- `public/data/P30-round-002.json` is the sanitized, aggregate-only public
  record for the rejected authored-presentation critic round.
- `public/data/P30-round-005.json` is the sanitized, aggregate-only public
  record for the rejected duel-contact critic round.
- `public/data/P30-round-006.json` is the sanitized aggregate public record for
  the frozen duel-contact candidate. Builder integration passes, but the fresh
  independent critic rejects it at 23/100 with 0/3 focused and 0/6 overall
  wins. Combat camera presentation is the active Round007 gap.
- `public/data/P30-round-007.json` is the sanitized aggregate public record for
  the selected adaptive duel camera. Every candidate-runtime technical gate
  passes, but the fresh independent critic rejects it at 34/100 with 0/3
  focused and 0/6 overall wins. Combat FX language is the active Round008 gap.
- `public/data/P30-round-008.json` is the sanitized public record for the
  selected combat-FX candidate frozen at
  `5359f91bad13fe83e70169231e519911a8fbebc4`. Root reproduced all six selected
  actual-game captures byte-for-byte and passed all 16 technical gates. The
  fresh independent critic is running; no quality score, blind win, verdict,
  or acceptance is claimed.
- `public/data/capture-manifest-latest.json` remains intentionally pinned to
  accepted P00; rejected P30 evidence does not displace it.
- `public/captures/P00/round-001/S01_Explore.png` is generated by Unity, not by
  the site.
- `public/captures/P30/round-001/` contains candidate-only S01, S02, and S04
  browser captures. They are failure/revision evidence, not AAA acceptance.
- `public/captures/P30/round-002/` contains only the candidate Critic S02, S04,
  and S06 captures. They remain rejected candidate evidence and are not
  accepted captures.
- `public/captures/P30/round-005/` contains only the candidate Critic S03, S04,
  and S05 captures. They are byte-identical rejected candidate evidence and do
  not advance the accepted-latest manifest.
- `public/captures/P30/round-006/` contains exact candidate-only S03, S04, and
  S05 captures. S04 is the latest rejected candidate linked by the ledger; it
  does not advance the accepted-latest manifest.
- `public/captures/P30/round-007/` contains exact selected builder S03, S04, and
  S05 captures refreshed from the critic run. They are rejected evidence, not
  accepted captures, and do not advance the accepted-latest manifest.
- `public/captures/P30/round-008/` contains exact frozen selected-candidate S03,
  S04, and S05 captures. They are pending critic-target evidence, not accepted
  captures, and do not advance the accepted-latest manifest.

The site never hosts local benchmark originals, composites, or private
comparison metadata. Completed P30 critic rounds publish only aggregate
outcomes and public seal hashes. Round008 publishes only the selected frozen
candidate and technical receipt while its independent critic is running. The
global latest manifest stays byte-for-byte pinned to accepted P00 until a later
round is accepted.
